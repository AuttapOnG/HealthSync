# Zepp Life MCP POC

Date: 2026-06-27

## Purpose

Use `zepp-life-mcp` inside this project as a POC/reference path for Zepp Life
login/session access. This keeps the experiment repeatable from the HealthSync
repo instead of depending on notes or tools outside the project.

This is POC-only for now. HealthSync should not depend on an MCP server at
runtime until the Zepp source path is proven and the adapter boundary is clear.

## Included Project Files

- `requirements-poc.txt`: installs the pinned `zepp-life-mcp` GitHub package.
- `docs/zepp_life_source_poc.md`: product/source-path decision record.
- `scripts/zepp_life_login_weight_poc.py`: tiny read-only parser/API POC owned
  by HealthSync.
- `.env.example`: local environment placeholders for the HealthSync-owned API
  POC script.

## Install

From the HealthSync repo:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-poc.txt
```

The package is pinned to commit
`d0d45f4d4649a84653b782172a0b1d8dc2cfa91a` so the POC does not silently drift.

On Windows consoles using a non-UTF-8 code page, set this before running
`doctor` or `sync` because the upstream CLI prints some non-ASCII status text:

```powershell
$env:PYTHONIOENCODING="utf-8"
```

## Cloud Session Setup

Use this when the goal is logging in to Zepp Life directly rather than waiting
for an export file.

1. Open `https://user.huami.com/privacy2/index.html`.
2. Sign in to the Zepp Life account.
3. Open browser DevTools.
4. Find the `apptoken` cookie.
5. Configure the MCP tool locally:

   ```powershell
   zepp-life-mcp setup --mode cloud_session --token "<apptoken>" --user-id "<userId>" --region eu
   zepp-life-mcp doctor
   ```

Use the actual region for the account. If cloud access fails, verify token,
user id, and region first.

## Export File Setup

Use this as fallback when cloud/session access is incomplete or unstable:

```powershell
zepp-life-mcp setup --mode export_file --export-path C:\path\to\ZeppExport
zepp-life-mcp doctor
```

## Sync And Inspect

```powershell
zepp-life-mcp sync --start-date 2026-01-01 --end-date 2026-06-27
zepp-life-mcp serve
```

For HealthSync's own minimal parser/API POC, use:

```powershell
python scripts/zepp_life_login_weight_poc.py --mock-response data\samples\zepp_life_weight_api_response.json
```

or with local environment variables:

```powershell
$env:ZEPP_HOST="api-mifit-us3.zepp.com"
$env:ZEPP_USER_ID="1234567890"
$env:ZEPP_APP_TOKEN="<apptoken>"
python scripts/zepp_life_login_weight_poc.py
```

The script also loads `.env` from the repo root automatically. `.env` is
ignored by git; keep real tokens there and keep `.env.example` as placeholders.

For the Zepp/Huami privacy page session, `ZEPP_HOST=api-mifit.huami.com` is the
host observed in DevTools. The HealthSync POC script first tries
`/users/{user_id}/members/-1/weightRecords`, then falls back to `/users/{user_id}`
when the profile contains the latest weight but the weight record list is empty.

## Security

- Do not commit real `apptoken` values.
- Do not commit raw export archives, proxy captures, cookies, or local SQLite
  databases generated by POC tools.
- Prefer keyring-backed setup for `zepp-life-mcp`.
- Keep HealthSync's future production source adapter read-only until endpoint
  behavior is proven.

## Decision Impact

- `zepp-life-mcp` is now a project-tracked POC aid.
- The preferred login/session discovery path is browser login at
  `user.huami.com` plus `apptoken` cookie extraction, because it is simpler
  than phone HTTPS proxy capture.
- The eventual HealthSync adapter should still live under
  `healthsync/sources/` and return canonical models directly.
